# Acceptance

This file lists each v1 acceptance criterion of `docs/01-product.md` §6 and each phase C scenario of `docs/BUILD.md` §4 (step 3 on Compose, steps 4 and 5 on the target environment). For each one it gives the evidence and a status.

Status values:
- `proven`: a test asserts the whole criterion. A criterion can be proven by two or three tests when each part is asserted by one of them.
- `partial`: some parts are asserted. The row says what is missing.
- `not proven`: no test asserts it.

Kinds of evidence:
- **in-process**: pytest against the real z-server app and a real Postgres. `server/tests` drive the agent side with `RecordingExecutor` and `ScriptedRunner`, and use the fake GitLab OIDC provider and the fake tools. `runner/tests` run the real runner with the OpenHands backend against the fake LLM and a fake z-server. `cli/tests` run `z` against the real z-server served by uvicorn. `packages/z-common/tests` and `ui/tests` (vitest with MSW mocks) are unit and component tests. All of them run in CI (`ci.yml`, jobs `python` and `ui`).
- **Compose e2e**: `tests/e2e/test_compose_mission.py`, on the full Compose stack with LiteLLM, the fake LLM and the hardened runner container (`e2e.yml`, job `compose`). It has two tests.
- **kind**: `e2e.yml`, job `kind`, which installs the Helm chart on a kind cluster.

The Playwright scripts in `ui/e2e/` are run by hand and not in CI, so they are not counted as evidence. The cited tests in `server/`, `runner/`, `cli/`, `packages/` and `tests/unit/` were run at the commit of this file and passed. The latest results of the CI-only jobs (Compose e2e, kind, helm, ZAP) were not checked when this file was written.

Test references are written as `file::function`.

## Not proven yet

- Every run against real systems: the inferX models (step 4, the 95 % valid-output rate, live Inference metrics), GitLab OIDC and the GitLab API, Jira, Microsoft 365.
- An install on a real k3s cluster, and any install with `values-k8s.yaml`.
- The seed playbooks run as missions: `weekly-vuln-triage`, `bulk-dependency-upgrade` and `project-security-pre-review` are linted and loaded, but no test runs them. The scale scenarios (50 or 20 findings, 5 or 3 repositories) are not exercised.
- Phase C on Compose: only 2 of the scenarios run on the Compose stack. The rest are in-process.
- An agent renamed or duplicated as Atlas starting a mission with `@atlas`, from the web app, the CLI or Teams.
- Gaining a role at the hourly group re-evaluation (added to `z-approvers`).
- A connector that an admin imported from an OpenAPI spec used in a mission, and the 10-minute target.
- Tests that run in the sandbox during a dependency upgrade.
- ZAP on the API, authenticated, with high alerts failing the job.
- Web flows in CI: starting a mission, the Admin mapping dry run and the Inference screen are covered only by MSW component tests or by the manual scripts in `ui/e2e/`.
